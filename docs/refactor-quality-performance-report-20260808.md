## 高收益性能任务结果

### P1：报价列表 HTML/DOM 瘦身

- 原始 HTML：425,978 → 182,130 bytes，下降 57.2%，满足不高于 220 KB 且至少下降 45%。
- 初始 DOM：8,128 → 2,207 nodes，下降 72.8%；编辑 Dialog 100 → 1，筛选 checkbox 443 → 0（首次打开对应列才生成）。
- 浏览器资源请求：26 → 26，没有增加；固定 fixture HTTP p95：12.675 → 7.345 ms，没有回退。
- 11 列候选内容、数量、顺序、搜索、全选/全不选、重置、应用和本页复用逐项一致。
- 实际隔离写入验证了有效保存、删除、CSRF 拒绝、陈旧版本冲突和审计；无编辑/无删除权限的载荷和能力按权限裁剪。
- 局部刷新、分页、前进/后退后均读取当前响应数据；特殊字符和 `</script>` 安全恢复；桌面和 390px Dialog 字段完整且无横向溢出。

结论：瓶颈已由测量证实是重复 HTML/DOM，不是 SQL；不把文件拆分或压缩算作收益。

### P2：产品目录查询复用

- 基线 `/products` p95 117.682 ms，重复复测 109.840 ms；产品搜索完整页基线 34.683 ms，重复复测 32.247 ms。
- 当前 20 轮复算：`/products` p50 17.236 ms、p95 19.534 ms；`/products?q=HONDA` p50 8.497 ms、p95 9.341 ms。
- 三个筛选维度复用一次等价查询；616 组随机组合加 406 组运行快照的候选内容/顺序/计数一致。
- 品牌规范预览改为有权限用户按需触发；预览期间完整导航维持 URL/工具栏/历史一致，普通目录继续使用 fragment。

结论：重复读取和管理员首屏全量品牌预览均通过 SQL/请求计时证实；收益不依赖 Schema 变化。

### P3：缺失产品缩略图轻量占位

- 基线产品搜索每轮因缺图额外下载完整 `/products` 12–17 次；询价结果额外 2 次。
- 当前缺图响应为 245-byte、`image/svg+xml`、`200`、`no-store` 且带 `nosniff`，不再重定向。
- 浏览器首屏 15 张缺图均只返回占位图；目标 `/products` 页面请求只有一次，正常 PNG/304 行为保持不变，控制台错误为 0。

结论：重复完整页面 I/O 已由浏览器网络记录证实；占位图的具体视觉细节不作为性能收益。

### P4：OE 前缀匹配索引

- 0% 命中 CPU p95：577.572 → 11.756 ms，49.130 倍。
- 75% 命中 CPU p95：132.005 → 5.612 ms，23.522 倍。
- 100% 命中 CPU p95：3.940 ms；构建 p95 下降，峰值内存增加 1.5%。
- 新实现以排序键和二分范围替代逐键扫描；保留旧扫描算法只作为差分测试 oracle，完整 `CatalogMatch`、顺序、原因和容错结果一致。

结论：13,044 个键上的扫描成本和改善均已测量证实；未来目录增长幅度属于推测，不作为当前收益。

### P5：业务同步归档单次遍历

- 固定媒体 fixture 每次 apply 的 tar 读取由 4 次降为 2 次。
- 10 轮 p95：1,270.419 → 908.612 ms，改善 28.5%；无媒体路径 173.261 → 169.916 ms，无回退。
- 一次归档遍历分发产品图纸、产品图片和物料图纸，不把整包媒体驻留内存；归档验证摘要只读取一次。
- 文件数量、逐文件内容、数据库结果、路径安全、冲突处理、事务、审计和失败补偿保持一致；异常流保证关闭源归档。

结论：重复归档打开和 I/O 通过 `tarfile.open` 计数与固定 fixture 计时证实；异步同步的潜在收益只是推测，留在架构候选中。
