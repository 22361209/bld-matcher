# 成本核算独立试用

用户已确认进入 Docker 本机正式接入阶段，日常入口与权限见 [正式成本核算](costing.md)。本文保留独立验收环境的运行方法与记录。

本阶段验证查看、查询、修改、新建和复制成本。核算逻辑属于项目内 `app/modules/costing`，独立试用不依赖正式产品目录、供应商档案或 BOM。正式 5055 页面及 NAS 不随试用更新。

## 启动与停止

在项目根目录运行：

```bash
uv run python tools/costing_trial.py start
uv run python tools/costing_trial.py status
uv run python tools/costing_trial.py stop
```

默认地址为 `http://127.0.0.1:5056/`，仅本机访问。启动工具拒绝端口 5055，检测重复进程及端口占用；停止时核对进程身份，不影响正式服务。

试用服务并行处理请求，浏览器空闲预连接不会阻塞登录页；停止后允许复用旧连接留下的端口状态，但仍拒绝实际被其他监听服务占用的端口。

首次启动显式初始化独立库并显示一次随机登录口令。配置仅保存口令哈希，后续启动不会重置密码。可在初始化前通过 `BLD_COSTING_TRIAL_PASSWORD` 提供 12–256 字符口令；不要把口令写入仓库、命令历史或共享日志。已有环境遗失口令时应先保护数据并进行明确的凭证恢复，不能删除成本库重新开始。

已有访问配置但成本数据库缺失时，初始化和启动均会停止并提示恢复已有成本库，不会重建空库。

需要隔离验收数据或只读演示时：

```bash
uv run python tools/costing_trial.py start --data-dir /tmp/bld-cost-acceptance --port 5057
uv run python tools/costing_trial.py stop --data-dir /tmp/bld-cost-acceptance
uv run python tools/costing_trial.py start --data-dir /tmp/bld-cost-acceptance --port 5057 --read-only
```

默认持久数据目录为 `data/costing-trial/`。`costing.sqlite3` 保存核算单、修订和参考资料；`access.json` 保存会话密钥与访问配置；`server.log` 保存服务日志；`previews/` 仅保存待确认导入。该目录由 Git 忽略，Docker 构建已有的 `data/` 排除规则同样适用。

该入口是本机验收服务，不作为多用户正式部署入口。Web 工厂不创建数据库或更改密码；初始化在启动服务前执行。导入和编辑通过登录、CSRF 与权限控制的应用接口进行，自动化不得直接修改运行数据库。

## 日常使用

1. 在“型号成本”按型号、名称、车系或车型查询，可筛选摆臂/球头及完整/待补充状态。列表默认按产品编码升序排列，查询和翻页保留当前排序，也可手动切换为“最近修改”。
   每个数据列的列头筛选按钮支持勾选多个值，各列条件同时生效，先筛选全部型号再分页。列头边缘可拖动调整宽度；操作列只提供操作及列宽调整。更新时间在成本详情的型号资料下方显示。
2. 打开型号直接修改明细，整单保存。页面计算与保存调用同一核算服务；计算显示最多六位小数，输入和内部 Decimal 精度独立保留。
3. 新型号优先选择“复制新建”，填写新型号后修改差异项。复制件保存后有独立记录和明细身份，原型号不受影响。
4. 没有相似型号时点击“新建成本”，可以空白开始或加入常用项目。未知费用可暂时留空保存，记录显示待补充。
5. 修改记录自动保存可信操作人、时间、版本及修改前后内容。版本冲突时页面保留输入，另开最新记录核对，不能直接覆盖他人修改。

## 算法与单位

所有金额为人民币单件成本。重量 kg；材料和运费单价元/kg；纸箱尺寸 cm；打包带单价元/m。

| 方式 | 算法 |
| --- | --- |
| 直接金额 | 本行金额 |
| 按件计算 | 单价 × 每件用量 |
| 按重量计算 | （单价 × 单件重量 + 单件加工费）× 每件用量；加工费缺省 0，用量缺省 1 |
| 包装分摊 | （纸箱单价 + 打包带长度 × 打包带单价）÷ 每箱装箱数 |
| 运费 | 重量 × 运费标准 |
| 调整/返还 | 本行正向或负向金额，仅此方式允许负金额 |

打包带长度沿用原表：`((长+高)×4+(宽+高)×4+(长+宽)×2)/100` 米。每箱装箱数必须大于零；打包带单价为零时可以不填尺寸。

明细计算成本、人工核定成本、理论废料参考额和实际废料抵减分开保存。核定成本留空时采用明细计算成本；实际废料抵减再从采用成本中扣除。已知项目小计不代表完整成本，待核对或缺项状态始终显示。负理论废料、过量抵减等必须人工核对。

最低含税售价采用用户更正的口径：抵减后成本÷0.8×1.1。先按成本占80%、管理成本占10%、净利润占10%计算，再乘1.1得到含税价；例如成本100元对应137.50元。仅在最终结果向上取到分，中间不舍入，避免舍入后低于计算下限；抵减后成本未知或为负时不生成最低价。建议含税单价默认跟随最低价，只在成本编辑页面手动调整；手动价格保存后随成本变化或公式更正仍保留，清空后恢复自动跟随。旧型号读取时补算售价，不改写已有成本、版本或原表利润字段。

## 原工作簿导入

“导入核对”选择现有 `.xlsx`，先预览再确认。支持摆臂、球头和配套参考表。单次上传最大 12 MiB，另有限制解包体积、行数、列数、型号数及单型号明细数。

- 不修改源 Excel。保存来源工作表、行、原值、公式、缓存和摘要。
- 识别常规计价公式，小计行不重复入账。特殊公式按金额快照保留并标待核对，不能把公式文本作为任意代码执行。
- 区分空值与零，保留负向返还、人工核定与实际抵减。理论废料仅作参考，不自动覆盖实际抵减。
- 全表参考资料与成本单在一个 SQLite 事务中提交；失败整批回滚。已有型号会阻断导入，不覆盖现有记录。
- 预览绑定当前登录会话，有效期一小时，确认只能使用一次。过期或再次登录需要重新预览。进程中断后先查询结果，重新导入仍受重复型号保护。
- 纸箱和费用参考资料只用于新选择时带入。以后修改一张成本单不会自动重算其他型号。

## 验收和后续接入

```bash
uv run python scripts/verify.py
uv run python -m unittest discover -p 'test_costing*.py' -v
```

完整验收包括纯核算、持久化、事务回滚、来源保护、并发冲突、导入边界、认证/CSRF、独立启动及 JS 行为。浏览器还需检查桌面/窄屏、键盘录入、保存重开、复制隔离、查询、导入预览与错误保留。

独立试用阶段验收记录：统一验证入口通过，734 项 unittest 完成（5 项原有跳过），72 项开发模块 pytest 通过。原有桌面 1440px、窄屏 390px、Tab 连续录入、缺项保存后补全、保存重开、复制独立及并发冲突保留输入检查通过。新增售价和列筛选在隔离环境验证跨页候选、多选翻页、多列组合、鼠标拖动列宽并刷新保留、缩至最小列宽后筛选按钮仍可用，以及手动建议价保存重开、成本变化保留人工价和清空恢复自动。桌面 1280px 与窄屏 390px 页面无横向溢出，明细表和列表内部滚动正常。

2026-11-05 更新 5056 后，经认证接口核对全部 443 个原型号的售价公式；更新前后型号身份、版本、更新时间和抵减后成本摘要一致，验收数据仅写入临时环境。

原工作簿经登录页面预览并确认导入 443 个型号（329 个摆臂、114 个球头），包含 9902 项明细；排除 1 条汇总行和 22 个空占位，已识别公式及摆臂原表汇总对账无差异。316 单资料完整，127 单因缺项、特殊公式或异常参考值待补充/核对；“导入成功”不代表这些待核对数据已获得业务确认。验收用新增、改价及冲突数据仅留在临时验收环境，提供给用户的试用库只导入原工作簿。

试用数据是独立数据，不会自动与 NAS 同步。正式接入前需确认录入便捷性及待核对口径，再通过现有正式迁移机制接入数据、权限和导航，复用同一核算核心。不得把成本写入目录销售价，也不能用本机试用库覆盖正式产品库。

需要保留试用数据时使用 SQLite Backup API 一致性快照，并保护访问配置；不要复制活动中的 DB/WAL/SHM 组合。试用停止后仍保留已有成本。
