## P1：报价列表 HTML/DOM 瘦身

- [x] P1-A：把每行一套完整“修正报价”表单改为一个复用 `<dialog>` 和一份 CSRF 表单。
- [x] P1-B：每行只输出修正按钮和按当前权限裁剪、安全序列化的记录数据。
- [x] P1-C：由 `static/pages/quotes.js` 填充字段、版本号、编辑地址、删除地址和确认文案。
- [x] P1-D：11 个列筛选器初始只输出面板外壳；完整候选数据保留在同一响应的安全 JSON 中，首次打开时生成 DOM。
- [x] P1-E：分页、筛选、局部刷新和前进后退后只读取当前页面数据，禁止复用旧记录。
- [x] P1-F：在隔离数据库中验证保存、删除、版本冲突、CSRF、服务端校验、审计和权限。

基线和验收：

- 基线 `/quotes` 未压缩 HTML 为 425,978 bytes。
- 重构后未压缩 HTML不高于 220 KB，且至少下降 45%。
- 初始 DOM 节点至少下降 40%，浏览器请求数不得增加。
- 11 列候选的内容、数量、顺序、搜索和筛选结果逐项一致。
- 无编辑权限时不输出编辑数据；无删除权限时不输出或触发删除能力。
- 固定环境 HTTP p95 不得回退超过 10%；路由清单和数据库 Schema 不变。

实测结果：未压缩 HTML 425,978 → 182,130 bytes（下降 57.2%），初始 DOM 8,128 → 2,207 nodes（下降 72.8%），资源请求保持 26 个，HTTP p95 12.675 → 7.345 ms。11 列候选、桌面/390px、权限、保存、删除、版本冲突、CSRF、审计和浏览器历史均在隔离数据库中通过；命令见 `scripts/benchmark_quotes.py`。

## P5：业务同步归档单次遍历

- [x] P5-A：减少 apply 阶段对同一 tar 归档的重复打开和遍历。
- [x] P5-B：在一次媒体遍历中分发产品图片、客户资料和物料图纸，不把整包媒体驻留内存。
- [x] P5-C：验证摘要、路径安全、链接、重复目标、大小限制、事务、审计和失败补偿。

基线和验收：

- 初筛媒体样本为 51,095,342 bytes、2,295 members（其中 2,293 个媒体文件），3 轮 apply p50/p95 为 1,805.573/1,816.001 ms，归档每轮打开 4 次；该样本只用于确认高收益方向。
- apply 归档打开次数降至最多 2 次，摘要读取不得增加。
- 至少 10 轮固定 fixture 的 apply p95 至少下降 15%，无媒体路径不得回退超过 10%。
- 文件数量、逐文件 SHA-256、数据库结果、冲突处理和失败补偿完全一致。

实测结果：固定 52,982,785-byte、2,297-member fixture 的 10 轮 apply，归档读取由每轮 4 次降为 2 次，p95 从 1,270.419 ms 降至 908.612 ms（改善 28.5%）；不导入媒体时 p95 从 173.261 ms 降至 169.916 ms。独立 review 后补强异常流关闭和重叠媒体目录映射，32 个业务同步测试通过；fixture 准备和复测命令见 `scripts/benchmark_business_sync.py`。
