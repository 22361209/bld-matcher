# 性能候选延期清单

- 状态：本轮不实施
- 日期：2026-08-08
- 适用范围：P1–P5 之外的性能候选

本清单不以总代码行数下降为目标。只有经过专项测量、确认收益和风险后，候选才可以进入后续实施计划。需要 API、数据库 Schema 或架构变化的项目必须单独授权，并按项目宪法补充 ADR。

## 无需 Schema 变化的候选

### 已有证据，但本轮收益或优先级不足

- 客户报价汇总 N+1：16 个客户触发 16 次汇总查询，但当前累计约 0.172 ms；数据规模扩大后再评估批量聚合。
- 报价筛选候选 SQL 合并：11 个字段分别执行 facet 查询，但当前 172 行数据下全部报价 SQL 仍不足 1 ms；P1 只处理 HTML/DOM，不把文件拆分或 DOM 延迟计算作 SQL 优化成果。
- 静态资源缓存：暖加载仍产生 22–33 个条件请求；需要先建立可靠的内容版本标识和失效策略。
- 请求级连接复用：客户详情产生 12–18 个 PRAGMA 调用，约 1.45–2.01 ms；必须先证明事务边界和并发行为安全。
- 权限快照复用：HTML 请求固定读取多组权限数据，但当前通常低于 0.1 ms；必须保证权限修改即时生效。
- 询价预览结果复用：分析和导出会重新读取工作簿并重新匹配；P4 完成后再测剩余收益，缓存键必须覆盖源文件摘要、目录版本、匹配列、价格参数和调整项。
- 业务同步版本计数或摘要缓存：需要先证明失效和跨设备一致性，再决定是否减少重复摘要读取。

### 只有代码证据或推测，需先建立专项 workload

- 产品图片上传可能存在验证解码和缩略图生成的重复解码。
- XLSX 清理器会把 ZIP members 内容保留在内存，大文件峰值内存尚未测量。
- 图纸 ZIP 按结果行逐项查询和读取文件，大批量场景尚未测量。
- 首页和询价页 TTFB 较高，但尚未用分阶段计时区分查询、匹配、模板和文件处理。
- `data.json` 当前约 1.15 MB；暂时没有证据支持流式 JSON 能带来高收益。
- 大型媒体同步可评估异步执行，但必须先有统一任务机制，不能在请求线程伪造后台任务。

## 需要 Schema、API 或架构变化的候选

- 产品自然排序持久键或专用索引：可能消除 `SCAN products` 和临时排序 B-tree，需要 Schema 迁移、历史数据库 fixture 和 ADR。
- 报价列表数据 API 化、虚拟滚动或降低服务端分页大小：会改变页面协议或请求形态；本轮明确保持每页 100 条且不新增请求。
- 持久化缓存表、同步 revision 字段或跨进程缓存：涉及 Schema、一致性或部署结构变化。
- 大媒体异步导入/导出：需要统一任务队列、查询、取消和结果协议，属于架构变化。

## 明确排除

- 字体优化不纳入本轮，也不作为 P1–P5 的性能成果；需要用户再次明确授权后才能规划。
- 不通过 HTML/CSS/JavaScript 压缩、弱化测试、删除错误处理、审计、事务或回滚逻辑来制造性能或代码量收益。
- 不修改当前运行数据，不在当前数据库执行保存、删除、导入或同步验收。
