## 过期兼容层候选

- `app.py` 的 413 处理器仍识别已下线的 `/product-data-sync` 路径并尝试跳转到不存在的 `product_data_sync` endpoint；`templates/_nav.html` 也保留同名 `active_page` 标记。仓库内没有运行时路由，相关 Web 测试均明确标记为“已由业务数据同步取代”并跳过，但无法从仓库证明没有旧书签或外部调用方。该路径属于错误处理兼容面，本轮不删除；后续应先增加明确的已下线路径合同，再决定返回 404、410 或统一入口。
- `tests/test_app.py` 的兼容测试入口看似只做转发，但仍支持开发者和外部脚本直接运行 `python -m unittest tests.test_app`。在确认所有 CI、IDE 和本地调用方迁移前不得删除。

## 仍有消费者的旧产品同步基础设施

- `app/modules/products/sync_repository.py` 仍被品牌规范化/同步合同测试使用，`sync_infrastructure.py` 仍被运行治理测试使用。虽然独立产品数据同步页面已下线，这些模块仍承载业务数据同步兼容和包检查能力，不能按“旧名称”直接删除。
- 五个旧 `/product-data-sync` Web 场景目前被跳过。删除测试和相关 fixture 会降低历史兼容证据；应在正式退役上述基础设施时一并处理，而不是为减少测试行数提前删除。

## CSS 与前端资源候选

- 共享 CSS 中存在名称或声明相似的响应式、表格和工具栏选择器，但它们处于不同 cascade 顺序和页面上下文。没有覆盖全部页面、权限和断点的渲染证据前，不做自动去重或合并。
- `base.html` 的部分可选 CSS/JavaScript 在某些页面只执行无操作初始化。报价页已通过可选样式 block 和浏览器请求对比，安全停止加载三份未使用 CSS；其他页面没有同等级浏览器证据，暂不继续裁剪。

## 需要专项工具或契约的候选

- 未使用的 JavaScript 导出只能由静态模块图证明一部分；模板动态入口、内联 `data-*` 协议和浏览器全局事件仍可能消费。后续如引入 bundle/metafile 或模块图检查，可再审计。
- 模板宏和测试 fixture 的结构相似不等于重复实现。后续可按实际修改频率和缺陷记录决定是否抽取，避免为减少行数制造跨域耦合。
