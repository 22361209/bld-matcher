# ADR 0040：Docker 容器内手动发布程序快照

状态：接受，2026-11-05。

## 背景

本机和群晖的 Web 服务均使用 Gunicorn。日常调整成本表格和计算代码也曾要求重建镜像。正式服务使用各自的业务数据，NAS 只访问局域网的 Git 仓库，发布端可以是不同电脑。

## 决策

完整构建生成镜像内运行文件与部署配置的 SHA-256 清单。快速入口将用户指定的代码准备到容器内独立版本目录，对照镜像和当前运行版本检查文件及变更片段。检查通过后写入版本指针并触发 Gunicorn 换代，每个 worker 启动时固定自己的代码、模板与静态资源目录。数据库、上传与输出继续使用原挂载目录。依赖、配置、迁移及发布工具本身变化要求完整更新。

本机在完整验证前后核对同一份工作树内容。群晖的发布电脑验证具体提交，再通过 SSH Git 推到 NAS。管理员安装的固定命令以 deploy 身份从本地 bare 仓库导出指定提交，仅将归档传入已核对身份的容器；业务数据和密钥不随代码发布。

## 验收与代价

快速入口等待两个 worker 都加载候选，核对 HTTP 版本、就绪和登录页探针，失败时切回上一版并复验。若切换期间容器重启，启动入口恢复上一个已确认版本。回退只影响代码，因此凡需要改变持久数据的发布必须走完整更新。快照随容器保存，重建容器从镜像版本启动。操作者可从 Git 重发期望的代码。

把宿主工作区直接挂载为应用根会让进行中的修改提前进入正式请求。每次完整重建则有清晰的镜像版本，但小改动也需经过备份与迁移。手动发布快照保留明确的切换时机，代价是需维护允许快速发布的文件范围及每台 NAS 的受限命令。
