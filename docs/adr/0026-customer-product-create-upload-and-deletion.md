# ADR 0026: Customer Product Create-Time Drawing Upload And Deletion

- Status: accepted
- Date: 2026-08-07
- Owners: BLD
- Partially supersedes: ADR 0024 中“图纸文件永不物理删除、报价图纸关联只由报价仓储清理”的绝对约束；ADR 0025 中“客户商品行不提供删除、版本与文件永不物理删除”的约束

## Context

客户产品建立后才能进入图纸弹窗，导致新增时已经拿到的客户图纸必须二次操作。错误建立的客户产品也没有删除入口，BLD 号又不可修改，只能长期保留错误行。现场确认的新要求是：新增客户产品时可直接拖入一份客户图纸；整个客户产品可删除，并同时清除其上传的图纸。

删除横跨客户产品、双图纸位、图纸版本文件以及报价行的图纸版本关联。数据库没有依赖这些表的级联删除，文件系统操作也不能和 SQLite 提交天然组成同一个事务，因此必须显式定义依赖顺序和补偿边界。

## Decision

1. **新增时可选客户图纸**：新增客户产品表单可携带一份 PDF、PNG、JPG 或 WEBP 客户图纸及可选版本代号。服务端沿用既有文件签名、大小、路径和原子落位校验；商品、客户图纸位、V1 文件、审计记录在同一个客户产品 Unit of Work 中提交。任一校验、落位或数据库提交失败时，商品行、图纸元数据和文件全部回滚。
2. **删除权限与确认**：删除使用既有 `delete_customers` 权限，通过带 CSRF 的 POST 路由执行。页面危险操作确认必须点名客户产品编码和 BLD 号，并说明 BLD 图纸、客户图纸、全部历史版本、实体文件以及报价图纸关联都会删除且无法恢复；报价记录本身保留。
3. **客户产品拥有完整删除生命周期**：删除时在同一个 SQLite 写事务中按 `quote_record_drawings` → `customer_drawing_files` → `customer_drawing_groups` → `customer_products` 的顺序显式清理。这里是 ADR 0024“报价仓储独占关联写入”的窄例外，仅用于删除关联源文件时维护引用完整性，不提供一般报价编辑能力。
4. **文件删除采用两阶段补偿**：取得 SQLite 写锁并读取稳定文件快照后，先将该客户产品的文件原子移动到 `data/customer_files/.deleting/` 隔离区，再删除数据库记录并提交。提交失败时反向移动恢复；提交成功后永久清除隔离文件。最终清除异常记录错误并保留隔离证据，不把已提交的数据库删除伪装成可重试失败。
5. **关联写入防止并发悬空**：报价图纸关联从普通 `INSERT` 改为同时带 `quote_records` 与 `customer_drawing_files` 存在条件的原子 `INSERT ... SELECT`。删除先取得 SQLite 写锁；因此任一端删除与关联并发时，只能得到“关联先完成后被依赖清理”或“报价/文件已删除、关联被拒绝”两种一致结果。
6. **不改变公共边界**：不新增数据库表、权限点或公共 API。客户产品删除和创建时上传都属于现有网页能力；操作继续写入持久审计日志。

## Compatibility

- 既有客户产品和图纸无需迁移；历史版本在客户产品存在期间继续完整保留并可回拨。
- 删除客户产品是明确、不可恢复的用户动作。删除后相同 BLD 号可按正常报价历史校验重新建立，但旧图纸版本不会恢复。
- 报价行本身、报价价格和其他业务字段不删除；只清除指向已删除图纸版本的关联记录。
- 客户资料库中非图纸文件、产品目录图纸与产品目录数据不受影响。

## Consequences

- 新增流程减少一次保存后再打开图纸弹窗的重复操作。
- 错误客户产品可以由拥有删除客户权限的用户清理，且不会留下活动路径中的孤儿图纸文件或悬空报价关联。
- “历史版本永久保留”调整为“客户产品存在期间永久保留”；删除整个客户产品是唯一会物理清除这些版本的路径。
- 客户产品仓储承担一个明确记录的跨域依赖清理例外；一般报价图纸关联与解除仍由报价领域负责。

## Verification

- 服务测试覆盖新增时上传 V1、非法图纸与提交失败的全量补偿。
- 删除测试覆盖空商品、双图纸位多版本、报价关联清理、跨客户拒绝、提交失败恢复、实体文件清除与同 BLD 重新建立。
- 报价测试覆盖报价或文件在预校验后被删除时，原子关联写入拒绝悬空记录。
- Web 和浏览器验收覆盖权限、二次确认、拖放选择、编辑弹窗桌面/移动排版、删除后列表与文件访问状态。
- 路由快照和 `uv run python scripts/verify.py` 必须通过。
