# ADR 0028: Customer Identity And Recent Capability Permission Catalog

- Status: accepted
- Date: 2026-08-08
- Owners: BLD

## Context

客户名称和客户编号会影响报价历史、合同来源和跨设备识别。它们此前与联系人、负责人等日常资料共用“修正客户”权限，普通维护人员可以在客户概览中直接修改，缺少与影响相称的授权边界。

与此同时，客户产品编码与双图纸位、报价行图纸关联、业务数据包中的产品/物料媒体和物料图纸页已经陆续上线，但权限管理页仍沿用较早的简短说明。物料图纸读取在新权限出现前对所有已登录账号可用，不能在补充权限目录时意外收窄既有访问。

## Decision

1. 新增可授权的 `change_customer_identity`（“变更客户名称与编号”）。客户名称和编号的变更只能由该权限保护的服务端入口执行，并记录变更原因与审计；它不再包含在 `edit_customers` 的日常资料维护范围内。固定管理员始终拥有该权限，迁移不自动授予任何非管理员角色或账号覆盖。
2. 新增可授权的 `view_material_drawings`（“查看物料图纸”），用于物料图纸的列表、预览和下载；`manage_material_items` 继续负责材料明细维护以及物料图纸上传/替换。
3. 迁移 037 对每个既有非管理员角色幂等补齐 `view_material_drawings`，保持此前所有已登录账号都可查看物料图纸的行为。全新数据库的 editor、user、viewer 基线也包含该权限。迁移不写入 `change_customer_identity` 的非管理员授权。
4. 权限目录文案明确记录已上线边界：客户查看/修正/删除覆盖客户产品编码与图纸，报价查看/修正覆盖图纸关联，业务数据同步覆盖五类数据集及显式媒体选择，材料维护覆盖图纸上传和替换。权限仍必须由服务端路由和服务层执行，菜单或按钮隐藏不构成授权。

## Alternatives

- **继续使用 `edit_customers` 变更名称和编号**：权限无法区分对日常联系人/负责人维护和对业务身份的高影响变更，不选。
- **将新物料图纸查看权限默认留空**：会使历史上可访问该页面的非管理员在升级后突然失去工作能力，不选。
- **只补充权限管理页面说明**：直接请求仍可能越权，且不能形成可审计的服务端边界，不选。

## Consequences

- 管理员需要在角色或账号权限页显式下放“变更客户名称与编号”后，非管理员才能进行这项高影响操作。
- 既有角色升级后继续能查看物料图纸；管理员可以随后按岗位收回该权限。
- 无新增公共 API、业务数据表或运行文件格式；迁移只增加 `role_permissions` 授权行。
- ADR 0023 的粒度权限模型继续适用；ADR 0025/0026 中以旧客户权限表达的客户产品/图纸能力由本目录澄清并收紧身份变更边界。

## Verification

- `tests/test_admin_permissions.py` 覆盖迁移 037 的幂等性、既有非管理员角色的物料图纸访问保留，以及不授予客户身份变更权限。
- 客户身份和物料图纸页面的权限回归覆盖服务端拒绝与授权后的正常操作。
- 提交前运行 `uv run python scripts/verify.py`。
