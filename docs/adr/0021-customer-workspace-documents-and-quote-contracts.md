# ADR 0021: Customer Workspace, Long-Lived Documents And Quote-Sourced Contracts

- Status: accepted
- Date: 2026-07-29
- Owners: BLD

## Context

客户主数据已经解决报价名称一致性，但只有名称维护，无法承载联系人、负责人、历史报价汇总和客户特定包装/单据模板。销售合同目前只能从空白表单开始，人工重复抄写报价明细，且没有结构化记录保存合同与来源报价、语言和币种之间的关系。

客户标贴、外箱、内袋、包装示例、出库单以及 PI、PL、CI 模板属于长期业务资料，不应进入按通用保留期清理的临时上传或输出目录。

## Decision

1. 客户主数据扩展可选客户编号、启用状态和负责人，并增加联系人子表。历史报价新增本机 `customer_id` 引用，由迁移按客户名称自动回填；名称字段继续保留为兼容快照。改名由客户服务先保存档案，再通过报价公开服务同步报价快照并递增报价版本；同步失败时客户服务补偿恢复原档案并记录审计，避免跨模块直接访问报价仓储。
2. 客户详情聚合客户基本资料、联系人、报价统计、最近报价和已生成销售合同。客户不再物理删除，停用状态用于停止新的业务引用，同时保留全部历史记录。
3. 客户资料库由 `customer_document_groups` 和 `customer_document_files` 表保存元数据、分类、语言、当前版本和每次批量上传的不可变版本。资料组可归档但不物理删除旧版本。
4. 客户资料文件写入 `data/customer_files/`。文件先写临时位置，完成大小、扩展名、内容类型和 SHA-256 校验后原子落盘；数据库或审计失败时补偿删除本次新文件。下载与预览必须经登录和 `manage_customers` 权限检查，并验证解析后的路径仍位于专用根目录内。
5. 报价单号明细允许选择同一报价单内的行，再明确选择合同语言。第一阶段只启用 `zh-CN`；`en-US` 作为不可选占位。系统预填客户、BLD 号、客户产品编码、报价单价、币种和备注，数量与交期仍由用户填写，MOQ 不作为合同数量。
6. 报价转合同要求所选行属于同一启用客户和同一币种，且每行只能存在一个非负、有限且处于允许上限内的报价价格。打开草稿时签发绑定报价行 ID、版本及完整来源快照哈希的防篡改选择令牌；生成时必须重新读取报价、重新复核客户状态并校验行数、ID、版本和快照。客户、产品、客户编码、产品资料、价格口径、币种及备注只在这次服务端读取中确定，之后不再二次覆盖，只接收用户填写的数量、交期和合同级字段。数量、单价、行金额和合计金额必须在 PDF 与人民币大写金额可承载范围内，所有 Decimal 溢出统一转为明确的校验错误。生成成功后在 `contract_documents` 保存合同类型、编号、客户、来源报价单号、语言、币种、文件引用，以及与最终 PDF 来源字段一致的不可变 JSON 快照和 SHA-256。销售合同渲染必须按币种显示，不得把 USD 等外币错误标成人民币或生成中文人民币大写金额。
7. `customer_id` 是设备本地数据库主键，不进入业务数据包；报价跨设备导入后按客户名称重新解析。本次实际覆盖的报价以导入后的客户名称解析本机 ID；仅客户包造成的改名则保留有效本机 ID 并规范化名称。同步改变既有报价的客户关联或其他来源字段时，版本从本机当前值只递增一次，不能采用包内较旧或相同版本。负责人账号同样属于设备本地身份，导入客户主数据时不得覆盖本机负责人。客户联系人、客户资料和合同文件第一阶段不进入业务数据同步包，随运行数据库与 `data/customer_files/` 一起备份。
8. 手工销售合同继续允许自由填写客户名称；若名称与启用客户精确匹配，则在 `contract_documents` 同时保存本机 `customer_id`，确保客户后续改名时合同历史仍归属于同一客户。

## Compatibility

客户名称、报价现有字段和手工合同入口继续可用。新增客户资料与报价转合同均为管理员界面能力，不新增公共 API。历史客户编号保持空白，不制造无业务含义的编号；历史报价关联由迁移自动完成，不要求人工补录。

## Consequences

- 客户页面成为轻量客户工作区，但不引入销售漏斗、跟进任务或复杂 CRM 自动化。
- 客户特定模板可长期版本化留存，NAS 备份必须同时包含 SQLite 和 `data/customer_files/`。
- 英文销售合同需要后续独立实现模板、条款和金额文案，不能仅翻译按钮后启用。

## Verification

- 历史数据库 fixture 验证 migrations 028–030 规范化客户名称、自动回填报价 `customer_id`、修复大小写重复编号和异常主要联系人且保留原记录，并兼容已经执行早期 028/029 的数据库。
- 客户领域测试覆盖资料编辑、停用、联系人、历史聚合和引用保护。
- 客户资料测试覆盖分类、文字资料、版本上传、路径穿越/格式/大小拒绝、下载和归档。
- 报价转合同测试覆盖必选语言、英文占位、跨客户/跨币种/停用客户拒绝、负价格、非有限价格、行金额与合计溢出拒绝、产品与价格篡改回填、客户改名及同步后的旧令牌拒绝、来源快照与 PDF 一致、空数量/交期、手工合同稳定客户关联和合同下载；业务同步测试覆盖跨客户报价覆盖时按导入名称重建本机关联且版本只递增一次。
- `uv run python scripts/verify.py` 与真实浏览器流程验收通过。
