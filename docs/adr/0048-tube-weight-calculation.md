# ADR 0048：管件按尺寸自动计算单件耗料重量

- 状态：已接受
- 日期：2026-11-22

## 背景

管件重量目前是手工值或 Excel 的已保存计算结果。修改外径、内径等参数不会重新计算。2026 年 11 月管件工作簿已提供计重公式，但部分保存结果与公式不一致；现有毛坯长度文本来自混合口径的成品尺寸列，不能据此自动推导计重长度。

## 决策

1. 增加独立的数值字段 `weight_length_mm`（计重长度，mm）及 `weight_mode`（`manual` / `auto`）。历史记录默认手工模式，长度为空，迁移不改变既有重量或推算缺失参数。
2. 自动模式按工作簿的固定系数计算每根管件的耗料重量：`((外径² - 内径²) / 4) × 0.02466 × (计重长度 + 公差 + 消耗) / 1000`，尺寸均以 mm 输入，结果以 kg 保存。不乘采购基数或成本单装配用量。
3. 页面输入改变时预览，服务端使用同一口径重新计算后保存；客户端提交的重量不能覆盖自动计算结果。缺必要参数时重量为空并说明缺项，非法数值不能保存，缺失不作零处理。手工模式保留独立填写重量的能力。
4. 借用件在查询及成本取重时沿用启用来源管件的有效重量。原有成本单保存的重量快照不批量更新，使用者仍需主动重新取重。
5. 计重长度不得从历史毛坯文本、成品规格或重量反推。Excel 的 O 列可作为后续经核对导入时的计重长度来源，按 m 转换为 mm；本次实现不执行导入，不批量采用源文件尺寸或重量。
6. 业务同步为包含自动计重字段的数据使用新版包，接收端校验计算口径与有效重量。兼容旧包时，不得把旧重量与新自动模式混合成不一致记录，也不得静默清空已确认的计重参数。
7. 用户于 2026-11-22 确认 `KG6028` 暂保留手工重量。原表 S312 使用不同系数，且未引用公差和消耗，暂不据此推断其物理口径。表单将此编号固定为手工模式；服务端和业务同步拒绝其通用自动模式，其余编号仍按各自实际参数计算，不按前缀统一公差或长度。
8. 本机历史资料尚未保存独立计重长度；在用户要求暂不导入工作簿的前提下，保留旧记录及重量，表单提示补齐并核对参数后切换自动。不得为批量启用而从成品长度推算，或把缺参记录的既有重量批量清空。

## 影响

新增数据库迁移，需要完整更新发布。成本取重继续通过管件服务，不新增外部 API、不更换数据库或框架、不改变历史成本。公式仅表示沿用原管件表的耗料计算口径，不能作为成品净重或其他材质密度公式。

## 验证

覆盖原表数值、mm/m 换算、单件与采购基数分离、缺失/零/非法值、自动重算和手工保留、历史迁移、借用与成本快照、业务同步新旧包兼容，以及表单桌面、移动端和输入错误状态。
