# 产品开发登记

本模块使用现有 BLD 页面、角色权限、CSRF、审计和 SQLite 迁移机制。架构决策见 [ADR 0034](adr/0034-product-development-register.md)。

## 集中录入

成品的八列树形 BOM 是主要录入入口：产品编码、产品名称、图纸状态、借用状态、借用编码、开发状态、责任单位、目标日期。可以就地新增同级或子件、按需生成常用结构草稿，并批量保存。数量、位置、获取方式、负责人账号、实际日期、材料和工序在次级详情维护。责任单位沿用轻量供应商主档；不将它当作负责人账号。

保存使用整单版本和单个事务，失败保留输入，不自动覆盖并发修改。完整交互与验收约定见 [树形 BOM 录入协议](ui/development-tree-grid.md)。参考图中的型号、单位和日期只用于隔离演示，不自动导入业务库。

## 数据与工作流程

- 开发单以四位核心系列归组，例如 `8461`。成品编码由用户填写，例如 `K8461LA`、`K8461RA`；单侧开发同样支持。
- 成品下的组件可以逐级增加，例如臂体、多个衬套、球头及球壳、球销、防尘罩。组件的本型号编码、借用编号、数量、位置和备注独立保存。
- `QD8461` 与借用源 `QD8070` 必须同时保留。借用来源主档具有独立永久 UUID，组件另存显示用借用编号；选择已有来源须明确操作，相同编码可以对应不同 UUID，不能据此自动合并。来源记录不可变，更换借用源时保留历史来源。编码不是数据库主键，也不作为自动判定共用的依据。后续 BOM 可分别展示两列；未来采购需求可按源编码汇总并保留使用型号。本模块不执行 MRP 或采购。
- 显式共用的组件关联同一开发任务。任务负责人、计划/实际日期、进度、供应商、材料、图纸要求和所采用资料因此保持同步。
- 复制另一侧时逐项选择共用或独立。独立任务重置完成状态与实际日期；图纸复制须另行确认，不从编码相似推断共用。
- 新开发、借用、现成选型与自制、外购、委外是两个独立维度。材料快捷类别与材料牌号、成形工艺分别保存。
- 工序按顺序记录执行方、负责人、日期及状态。成品满足量产条件、任务/工序及需图要求后，由成品负责人本人确认。部分成品完成时，开发单显示部分完成。

## 图纸和工艺文件

文件写入不可变修订目录；修订包含永久 UUID、文件大小、SHA-256、编号、版本标签、变更说明、上传人和时间。允许的格式由 `app/modules/development/file_validation.py` 管理，PDF 可预览，其余允许的源文件作为附件下载。

上传新版不改变已有采用关系。资料关联指向具体修订，升级时用户明确采用新版本。共用任务的采用关系同样共用；组件的本型号与借用编码仍各自保留。工艺文档关联开发单、成品、任务或工序，并保留草稿、发布、作废状态的修订历史。归档不删除被引用的文件与历史。

## 权限与部署

- `view_development`：开发资料查看。
- `edit_development`：开发资料维护；成品完成仍需要负责人身份。
- `view_development_files`：文件历史、PDF 预览与附件下载。

管理员依现有机制拥有全部权限。旧角色不自动授予新增开发权限。所有写请求携带 CSRF 与整单 `expected_version`；并发冲突要求刷新，不能覆盖另一人的更新。

迁移 `043_product_development_register` 是新增表和索引，不重建旧材料表、不重编码旧产品。正式应用前必须完成 SQLite Backup API 一致性备份与完整性校验，并获得运行库迁移及 5055 启用确认。2026-10-02 经用户确认已在 Mac mini 启用：备份保存在 `data/local-backups/development-043-20261002T173618Z/`，迁移前后 31 张既有表摘要一致，受管重启后的健康及业务探针通过。NAS 更新仍必须遵循 Git 流程，本次未连接或同步 NAS。

## 同步边界

开发单、分支、组件、共享任务、工序、借用关系和文件修订通过永久 UUID 重建。已有开发单出现差异时整单人工确认，时间较新不代表自动接受。重复导入保持幂等，包内缺少记录不表示删除。

开发文件使用独立完整性路径：同一修订 ID 不得对应不同内容；预览令牌绑定包和本机文件摘要，应用时再复核。只应用已接受记录及其文件，失败使用数据库事务和文件补偿恢复。旧包兼容及旧媒体行为不因本模块被顺手重构。
